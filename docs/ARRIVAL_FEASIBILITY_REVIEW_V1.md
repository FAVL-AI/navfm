## Comparator fidelity that must be demonstrated

The [official PlaceNav navigation source](https://raw.githubusercontent.com/lasuomela/PlaceNav/main/src/placenav/navigate.py) obtains a node from the Bayesian querier and sets `reached_goal` when that node equals the requested goal node. The [official Bayesian filter](https://raw.githubusercontent.com/lasuomela/PlaceNav/main/src/placenav/place_recognition/bayesian_querier.py) initializes from image-descriptor distances, updates a temporal transition/observation belief, and returns its maximum-probability node. Native goal declaration is therefore node equality; calling an added probability threshold the released STOP rule would be inaccurate. The [paper](https://arxiv.org/html/2309.17260v4) uses 5 Hz reference-route repetition. This study's 4 Hz schedule, chosen navigator, goal region, settled-stop metric and any calibrated terminal gate are explicit adaptations.

The [official ULVN core](https://raw.githubusercontent.com/hren20/ulvn/main/ulvn_core/navigation.py) implements normalized descriptor likelihoods, graph transitions, entropy-dependent prediction/observation fusion and a separate graph planner. Its [reproduction guide](https://raw.githubusercontent.com/hren20/ulvn/main/docs/REPRODUCTION.md) describes map assets, descriptor/adjacency alignment, learned local planners and a simulator acquisition pipeline. Extracting only terminal belief while fixing another navigator is a component adaptation, not reproduction of ULVN's full mapping/planning/navigation result. No ground-truth graph connectivity, occupancy map or live pose may silently enter the proposed RGB-only STOP arm.

Before execution, a versioned fidelity manifest must identify upstream source commits, local patches, encoder/checkpoint/preprocessing hashes, reference order/spacing, graph construction inputs, initialization, transition parameters, likelihood normalization, terminal-index/STOP rule, dwell, reset and tie handling. Deterministic descriptor-sequence controls must reproduce upstream node/belief behavior where the contracts coincide, then test every declared adaptation separately. Degenerate descriptors, missing frames and reset failures must refuse safely and retain a failure record. This note inspected source but did not load those models, run those controls or establish byte-level reproducibility.

The same reference RGB is available to all arms. Model-specific descriptors can differ if their identities, offline preparation cost, memory and online latency are recorded. RGB-derived graph construction is allowed only under the frozen common information boundary; extra reference coverage, privileged geometry or live localization is not. Each adapter's source-based native terminal declaration is retained as a diagnostic, so calibration cannot silently conceal fidelity errors. Reference-only or arithmetic replay is not motion evidence.

## Small finite layout and attempt design

Propose **six development-feasibility layout groups**, mutually disjoint in base geometry and disjoint from verifier-fitting/calibration layouts. They are explicitly accessed development data, never sealed test data. A single maintainer can curate these development layouts, but cannot describe them as independently custodied confirmatory data. Reusing texture variants or multiple starts in one geometry does not create a new layout. The two old accessed layouts may support setup diagnostics but do not replace the six new groups.

For each layout, predeclare two reference chains under one fixed lighting condition: one route with naturally repeated visual structure and one route with ordinary structure. Each chain supplies two fixed feasible starts, giving **four feasible tasks per layout**. Twelve reference acquisitions therefore cover six layouts times two routes; both starts and all arms share the exact corresponding reference images. No appearance-toggle variant requires another chain. This is a prespecified descriptive aliasing stratum, not an illumination or cadence intervention and not a causal aliasing experiment. All observations/references use the qualified 4 Hz contract; speed/alignment assumptions are declared. Two additional mismatched/absent-goal requests per layout form a separate negative-control stratum.

Three arms times three fixed seeds give **324 planned slots**: **216 feasible-goal navigation attempts and 108 passive goal-admission checks**. The first block is **one layout, one feasible task, three arms and three seeds: nine navigation attempts included in the 216**, not nine extra. This block checks acquisition, provenance, resets, scorer completeness, controller behavior, unintended-contact observation and resource accounting. Continuation is conditional on these integrity gates. It is not conditional on a favorable effect, and it does not permit threshold/checkpoint tuning after observing the block. All remaining attempts keep the original manifest and counterbalanced arm order. Safety/integrity failures halt the study; no outcome-selected replacement or automatic expansion is allowed.

Goal controls need an explicit common **RGB-only goal admission contract**, because the released route-following comparators expect a valid map goal node. An oracle absent-goal flag cannot be passed to the policy. Apply the same predeclared passive admission rule to every arm; freeze its thresholds on separate calibration data. Preserve the requested image, admission decision and any proposed association. A rejected request is an admission rejection, not successful navigation or demonstrated STOP-verifier abstention. An absent or otherwise unrepresentable native goal is recorded as **NOT_RUN_UNSUPPORTED_GOAL_INTERFACE** for closed-loop evaluation. Do not force it into an existing node, silently replace the requested RGB, or convert that refusal into a favorable STOP outcome. A false association by the passive rule is an admission false acceptance; it does not justify an unsupported navigation launch. An absent request has no valid correct-stop position and no metric-distance wrong-stop label. Controls are excluded from feasible-goal completion/time comparisons. The 108 control slots are reserved admission checks, not promised closed-loop episodes; the 324-slot ceiling does not manufacture outcomes for them. If the shared admission interface cannot be qualified, the stage remains blocked.

## Measurements and interpretation

Keep all planned slots and actual attempts in the ledger. Feasible-goal endpoints inherit the prior design: wrong-location voluntary STOP outside the 0.5 m goal-image capture region; collision-free settled completion; and restricted completion time `T*`, equal to valid completion time by 120 simulation seconds or assigned 120 otherwise. The final one-second settling motion threshold remains less than 0.01 m, with final distance at most 0.5 m. Two additional simulation seconds are reserved for terminal measurement, not new policy decisions. The legacy aggregate `wrong_stop` is retained separately. Missing mandatory measurement is UNKNOWN and blocks efficacy adjudication; it is never filled as a favorable zero or dropped.

Report for each layout and arm the three-seed mean over its four feasible tasks, along with every task/seed outcome. Compute the six paired differences for candidate minus each existing comparator and their sample SD using denominator **five**. Report mean, SD, range and the actual six differences; routes, seeds and frames do not increase the independent-layout count. Any interval based on a six-layout t approximation or bootstrap is exploratory and assumption-sensitive, not confirmatory evidence. All-zero events do not justify a zero-width uncertainty claim. As an illustration, zero event-positive layouts out of six gives a one-sided 95% upper bound of `1 - .05^(1/6) = .3930` on the probability that a layout contains any event, assuming independent identically distributed Bernoulli layout indicators. This is not an episode-risk bound below five percent.

Estimate each comparator's wrong-location baseline rate and completion/time tradeoff without choosing the most favorable seed. If the strong comparator's true wrong-stop rate is below .05, the earlier strictly greater-than-five-point reduction is impossible; the assumed .10 reduction requires baseline risk of at least .10. Pilot point estimates flag feasibility concerns but six layouts cannot reliably certify those population floors. No numerical target is lowered to make the candidate appear viable. Low or zero baseline events support revisiting the question or collecting separately justified development evidence, not a superiority conclusion.

Measure acquisition-to-command/STOP wall latency p50/p95/p99, missed deadlines, initialization/reference preparation time, simulation real-time factor, peak allocated/reserved GPU memory, system memory, bytes per admitted reference/episode, and total external storage. Report attempted versus moving seconds/distance, unintended contacts and post-stop contacts separately. Simulation time governs the horizon, dwell and delay; wall time governs process/resource limits. Contact filtering must preserve unintended robot/environment contacts while excluding specifically qualified wheel/floor support pairs. A shorter episode alone cannot establish safety. If contact observability fails, collision-free completion is not admissible.

The six-layout variance estimate, unknown joint distribution and selected development population **cannot validate the earlier 80-layout joint-power claim**. Retain the old 32/71/126 sensitivity arithmetic as assumptions only. Use this pilot to measure whether a larger design is plausible and to identify a budget/protocol decision, not to unlock test access. A later confirmatory study still requires new independent custody, source/analysis freeze and authorization.

| Hard ceiling | Remaining six hours cover overhead only, not more trials | **72 wall hours and 72 GPU hours; 50 GiB external storage** |

The navigation ceiling is **7.32 simulated hours**: 216 navigation attempts at 122 seconds each. The 108 passive admission checks have no navigation simulation allocation and never become extra navigation attempts. Their 600-second process reservations are conservative wall/GPU caps, not evidence that they consume a full episode or any motion time. Permitting navigation with an absent goal would require a new reviewed interface and resource contract. Serialized single-GPU reservation deliberately counts idle process time; actual device utilization is measured separately. The 600-second wall cap is an assumption, not measured throughput. Exceeding process, storage, memory or aggregate limits halts work and requires a new reviewed decision. All failed launches consume their original finite allocation. Architectures, learning schedule, exact trial count and label admission for the six-hour fitting allowance must be frozen before that allowance is usable; the allowance does not authorize a search until one model wins.

Physical/CAD/controller/contact qualification is a separate **blocked prerequisite**, not hidden inside these 72 hours. Current qualification cannot be completed by declaring it a twelve-process replay exercise. If faithful comparators, required fitting data, six layout groups or adequate reference coverage cannot fit the proposed allocation, the correct output is NOT FEASIBLE UNDER THIS CAP with the observed reason, rather than a weaker comparator or unreported extra compute.
