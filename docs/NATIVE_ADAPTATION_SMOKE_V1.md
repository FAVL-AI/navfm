## Native objectives and fixed examples

Separate `adapt_gnm_native_v1.py` and `adapt_nomad_native_v1.py` modules construct the strict released architectures and native losses. GNM uses native distance/action loss, Adam7e-4/betas(.9,.98), learn-angle cosine/sine labels and85×64 six-frame RGB history. NoMaD uses native goal-mask/noise/timestep/diffusion objective, AdamW1e-4,96×96 four-frame RGB history and eight action waypoints. Native image crop and ImageNet normalization are preserved. Both use chronological waypoint_spacing1 and measured corpus spacing0.049994826316833496m; temporal-distance labels remain steps, not metres.

Each fixed batch has two positive goals at current8→goal14 and two cross-trajectory negative goals with label20/action mask0. Train anchors are the first two admitted train trajectories; development anchors are the two original dev routes. The complete31-train/four-exposed-development partition mapping is explicit. History, positive/negative goal and label endpoints must remain in their partition; missing/admission-drift or padded out-of-range labels reject. The native loader's methods are reused with a fixed goal selector/direct source-image reads, avoiding cache writes to the admitted corpus. Four fixed pairs from two observation anchors repeated six times means24sample draws, not24independent trajectories or full-corpus adaptation.

GNM's release training dictionary is explicitly hash-trusted then normalized to a state dictionary; NoMaD's released bare EMA dictionary is loaded safely. Every load/reload is strict. No released optimizer/scheduler state is implied. NoMaD initializes the raw model and its initial EMA shadow from the same released EMA weights. The installed diffusers parameter-iterable EMA API is used explicitly (power.75,use_ema_warmup=true); the snapshot's older model/averaged_model whole-epoch interface is not silently invoked. Both smokes use constant LR, not a full-epoch scheduler; raw model, optimizer, constant-LR scheduler, RNGs and EMA shadow/counter are preserved separately. Deployment artifact is NoMaD EMA or GNM raw, with hashes in the ledger. This API adaptation and six-update test are not a claim of a completed native long-training run.

Development is eval/no_grad with model/optimizer/EMA state-digest nonmutation checks and restoration of per-module training modes plus Python, NumPy, Torch CPU and CUDA training RNGs. Fixed evaluation RNG909 makes pre/post stochastic NoMaD reductions comparable within this smoke without contaminating training draws. No development optimizer, EMA or BatchNorm statistics updates. The common metric uses the same two action-valid positive pairs and first five chronological waypoints, same metric scale; native horizon5/8 and objectives remain separate. NoMaD get_delta/ACTION_STATS normalization/inverse+cumulative roundtrip is asserted before use, without clipping. Sampling uses ten diffusion steps, goal-conditioned mask0 and one action sample per example.

Every update records finite gradient/state checks and actual optimizer step readbacks. PASS also requires changed raw parameter tensors, six completed updates, finite development outputs, complete strict resume/deployment reload and actual loaded-source provenance before/after training. These are engineering checks, not adaptation benefit, stop calibration or navigation competence. Losses/ADE/FDE are descriptive on the tiny exposed fixed batches.
