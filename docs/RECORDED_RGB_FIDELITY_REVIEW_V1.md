## ULVN native RGB and transitive model contract

The ULVN pin remains `e2f47fe3e2757a1ebdc041f4364dddd26a19f9f5`. Its [ROS encoder path](https://github.com/hren20/ulvn/blob/e2f47fe3e2757a1ebdc041f4364dddd26a19f9f5/BPL%20%26%20BASS/bass.py) defaults to **MegaLoc** and image size 320 by 320. `MyVPR` converts the image to RGB; preprocessing resizes the PIL image to that shape, converts to a tensor, and applies ImageNet normalization. This operation order differs from PlaceNav's tensor-resize path. The MegaLoc wrapper and ROS `MyVPR` each normalize the output. The mapping encoder has the model/wrapper normalization path without the additional ROS `MyVPR` normalization; preserve that source distinction.

ULVN's loader calls an unpinned `torch.hub.load` on `gmberton/MegaLoc`; its `--no_pretrained` switch does not disable the MegaLoc branch. That source pin alone therefore does not freeze executable encoder code or weights. The separately inspected official [MegaLoc code revision](https://github.com/gmberton/MegaLoc/tree/5fe0dd697c4a70ba3e23607f6716ab3c606b16db) is `5fe0dd697c4a70ba3e23607f6716ab3c606b16db`. The [model implementation](https://github.com/gmberton/MegaLoc/blob/5fe0dd697c4a70ba3e23607f6716ab3c606b16db/megaloc_model.py) includes its DINOv2 architecture locally, so there is no second DINOv2 hub/checkpoint download at this pin. This does not establish which mutable dependency revision produced the paper's experiments.

The model outputs **8448 dimensions**. ULVN's wrapper field `out_dim=512` is metadata and does not project the output. MegaLoc internally resizes dimensions that are not multiples of its 14-pixel patch size, making a 320-by-320 tensor **322 by 322** with antialiasing before feature computation. Freezing descriptors at 512 dimensions or claiming an effective 320-by-320 backbone input would be incorrect.

## Native reference graph boundary

ULVN's [mapping driver](https://github.com/hren20/ulvn/blob/e2f47fe3e2757a1ebdc041f4364dddd26a19f9f5/scripts/run_mapping_pipeline.py) orchestrates RGB encoding, FAISS indexing, graph construction and pruning. The [encoder](https://github.com/hren20/ulvn/blob/e2f47fe3e2757a1ebdc041f4364dddd26a19f9f5/RAVEL/scripts/encode_images.py) recursively collects and lexicographically sorts filenames and aligns successful decodes with descriptor rows. Native silent image skipping is unsuitable for a fixed replay population: a missing or undecodable admitted frame must fail the attempt rather than shrink the population after outcomes.

RAVEL builds its graph from RGB and derived visual descriptors/matches; it does not require live pose, depth, odometry, metric floorplans or ground-truth connectivity. Nevertheless it is not a generic temporal chain. Its [parameter analysis](https://github.com/hren20/ulvn/blob/e2f47fe3e2757a1ebdc041f4364dddd26a19f9f5/RAVEL/scripts/analyze_parameters.py) uses SuperPoint/LightGlue matches with fundamental-matrix RANSAC, selects base query 0 and a farthest valid visual neighbor, and derives a match threshold and visual-search radius through KMeans. This is data-dependent parameter estimation. The [matrix builder](https://github.com/hren20/ulvn/blob/e2f47fe3e2757a1ebdc041f4364dddd26a19f9f5/RAVEL/scripts/build_matrix.py) accepts pairs whose verified match count exceeds that threshold and normally retains weighted counts. The [pruner](https://github.com/hren20/ulvn/blob/e2f47fe3e2757a1ebdc041f4364dddd26a19f9f5/RAVEL/scripts/prune_topomap_nx.py) takes a maximum spanning forest and adds back nonforest edges with weight greater than 300.

Native RAVEL graph qualification therefore remains **BLOCKED** under this milestone's no-threshold-fitting boundary unless an already admitted, fully bound native graph is available. A fixed shared graph derived from permitted recording order can support an explicitly adapted component replay, but cannot be called native RAVEL construction or a faithful complete ULVN reproduction. Freeze graph node order, weights, construction rule and exact frame coverage separately from the encoders. Both methods receive the same permitted raw reference collection; they retain their different native descriptors and preprocessing. No ground-truth graph may replace visual construction.

## Replay acceptance and permitted claims

Before execution, freeze admitted raw-image hashes/order, reference/query roles, checkpoint and source digests, loading/preprocessing adaptations, actual descriptor dimensions/dtypes, graph condition and a finite inference/output budget. The proposed deterministic recording selection is the lexicographically first admitted development sequence, `prospective_v1_layout0_route0`, with reference indices `0,4,8,12,16,20,24,28` and query indices `1,5,9,13,17,21,25,29`. This provides eight references and eight disjoint query frames per encoder, totaling **32 encoder calls**, with proposed caps of **120 seconds reserved for the GPU worker and 300 seconds total wall time**. It is one technical sequence, not a sample of independent layouts or navigation episodes.

Metadata inspection verified that the admission record marks all four available trajectories as DEV, has empty TRAIN/TEST lists, and describes previously accessed kinematic-pilot material. The selected trajectory is its first lexical DEV entry; all 16 selected image hashes match its dataset mapping. The finalization record is COMPLETE and binds the same admission digest; finalization-file SHA-256 is `402c3e6f8bb7e6a6ee30fea1cb68c339954a68e74e7361523d377d06beec734d`. These checks establish eligibility and identity, not image quality or behavioral performance. The executable replay must enforce the same bindings before decoding.

Bind recorded acquisition times separately from a declared virtual adapter clock. These selected query frames are sparse samples from the recording; their capture intervals cannot be inferred from consecutive replay indices. The old synthetic descriptor-width cap and source freeze remain intact; real descriptors need their own explicit admission contract. A reused frame, synthetic clock or shared graph adaptation does not establish native sensing cadence.

Validation must establish strict checkpoint coverage, finite correctly normalized descriptors, reference/goal/node alignment, unchanged native belief/arrival behavior on those descriptors, deterministic reset/state isolation, and a mock-only STOP interface that cannot publish hardware commands. Preserve every attempted case and the first failure/timeout, with no replacement or outcome-driven rerun. Native ULVN arrival publication is still distinct from actuator STOP.

A successful fixed replay would establish only that the admitted recorded RGB and authenticated native encoders traverse the declared reference/graph adaptation and stopping-interface pipeline under the measured resource envelope. It would not establish native graph-builder fidelity, closed-loop navigation, wrong-stop reduction, completion, physical stopping, contact safety, unseen-layout generalization or novelty. Motion/plant/contact qualification and all study gates remain independent.

Source mapping is complete, and the preparation record reports both authentic assets available with bound digests. The final fixed replay contract and bounded implementation readback remain required before this note can support a measured qualification claim. No positive recorded-RGB inference result is asserted here.
