## F-M2-1: this is a critical methodological finding

The failure was not simply “two dependencies were missing.” The dangerous chain was:

```text
Undeclared imports
→ upstream-marked modules fail during collection
→ tests are skipped or not collected
→ pytest exits 0
→ archive reports a green suite
→ compatibility proof appears to have run
```

That means the gate’s previous proposition was effectively:

> No collected test failed.

But the intended proposition was:

> The complete declared compatibility suite was collected and passed.

Those are not equivalent.

The count change from:

* expected compatibility population: `26`
* observed compatibility population: `9`

was the only available signal that the proof had collapsed. A passing exit code was insufficient.

### Correct classification

I would record F-M2-1 as:

> **Evidence-completeness failure caused by silent test-population contraction.**

It threatens:

* compatibility claims;
* regression claims;
* archived gate summaries;
* fresh-environment reproducibility;
* any statement that “the upstream proof passed.”

### Required invariant

Every gate that relies on a named test population must enforce all three conditions:

1. Expected tests were collected.
2. No required test was skipped, deselected, or collection-failed.
3. All collected required tests passed.

For the upstream suite, the gate should fail unless the exact expected count is present:

```text
upstream_marked_expected = 26
upstream_marked_collected = 26
upstream_marked_skipped = 0
upstream_marked_failed = 0
```

Do not rely only on parsing the final pytest sentence. Prefer a machine-readable pytest report and explicit assertions over:

* collected node IDs;
* marker membership;
* skip reasons;
* collection errors;
* exit status.

The count should be pinned to the upstream commit and test-manifest hash, not treated as a timeless constant.

## F-M2-2: environment identity was semantically incomplete

This is also a substantial finding.

The earlier identity represented the installed environment but not the **effective import environment**. Because `PYTHONPATH` changes import resolution without changing the virtual environment’s installed package set, two shells could share the same identifier while executing different code.

Your correction—hashing `PYTHONPATH` and printing it on page one—is necessary and correctly located in the identity mechanism rather than only in documentation.

The key principle is:

> Environment identity must fingerprint the effective execution instrument, not merely the package installation.

### One further hardening

`PYTHONPATH` is necessary but may still be insufficient. The effective import graph can also be changed by:

* `sys.path`;
* `.pth` files;
* editable installs;
* `sitecustomize.py`;
* `usercustomize.py`;
* current working directory;
* `PYTHONHOME`;
* user-site packages;
* `LD_LIBRARY_PATH`;
* `PATH`;
* `CUDA_HOME`;
* dynamically loaded shared libraries.

You do not need to hash the entire shell environment indiscriminately. That would create unstable identifiers with little scientific value. But I would add a compact **effective-import fingerprint** containing:

```text
sys.executable
sys.version
sys.prefix
sys.base_prefix
sys.path
PYTHONPATH
PYTHONHOME
site.ENABLE_USER_SITE
site.getusersitepackages()
current working directory
```

For load-bearing modules, also archive their resolved source locations:

```text
torch.__file__
torchvision.__file__
navfm.__file__
vint_train.training.train_utils.__file__
cv2.__file__
matplotlib.__file__
diffusers.__file__
```

This provides direct evidence that the modules came from the intended instrument.

## The remaining hardenings

* checkpoint digest;
* dataset/split digest;
* evaluator commit;
* configuration digest;
* metric set/version;
* seed set;
* batch protocol;
* environment identity;

### 1b. Evidence classes

Recommended minimum enum:

```text
pipeline_smoke_test
random_init_control
checkpoint_sanity
baseline_evaluation
registered_experiment

```

Each class should define which outputs may enter paper tables.

### 1c. Contamination barrier

`make_tables.py` should refuse scientific tables containing:

* `random_init=true`;
* non-scientific evidence classes;
* missing checkpoint hashes;
* unregistered diagnostic runs;
* mixed environment identities unless explicitly allowed;
* incomplete seeds.

### 1d. Table lineage

Each rendered table row needs a machine-readable source record linking it to:

* run IDs;
* raw metrics;
* seeds;
* checkpoint;
* dataset split;
* evaluator commit;
* environment identity;
* preregistration commit.

### 1e. Scheduler-remedy identities

The two scheduler remedies must fork experiment lineage:

* continue under original horizon;
* explicitly redefine/restart schedule.

They must not be represented as equivalent resumes.
