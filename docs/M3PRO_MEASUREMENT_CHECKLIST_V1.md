# Consolidated M3 Pro geometry and measurement checklist

Status: preparation only; no physical measurements or robot actuation performed. Use the [source specification](M3PRO_LOADED_PLANT_SPEC_V1.md) and [parameter ledger](../configs/robots/m3pro_loaded_plant_spec_v1.json). Do not substitute X3, Muto or generic mecanum dimensions. Record source/file hashes, configuration, units/frame, uncertainty and unresolved values for every item.

1. **Identify and decode the available CAD first.** Use the complete manufacturer-distributed S3 file, preserving its observed hash. Record decoder/version, assembly/hardware revision, declared units and export settings. Export STEP or another inspectable assembly representation without flattening transforms. Confirm four 80 mm nominal wheel envelopes and component correspondence to the actual M3 Pro; filenames alone do not establish variant identity. Preserve export hash and source-to-export mapping externally.
2. **Extract contact kinematics.** Record each wheel's hub centre/spin axis and FL/FR/RL/RR order; roller count, profile/radius, local axes/positions and handedness; and which joints are passive. Validate frame transformations and sign conventions independently of the failed telemetry. If CAD omits roller mechanics, request the component drawing or measure only those missing dimensions using scaled photographs/calipers with uncertainty. Do not estimate dimensions from unscaled product images or choose them to make the simulation pass.
3. **Extract rear suspension geometry.** Record rear-pendulum pivot/frame, supported components, linkage and travel limits. Verify that solids correspond to real mobility rather than mere mesh assemblies. If geometry is absent, measure pivot/axle positions and travel; document how the assembly is supported. Passive stiffness, damping and pivot friction remain separate unknowns unless specified or measured.
4. **Specify the evaluated load configuration.** Record battery, compute, stowed arm pose, camera/sensor mounts and payload. Use manufacturer component mass/inertia data where traceable; measure missing masses and loaded COM. If only approximate inertias are feasible, state shape assumptions, frame, uncertainty and derivation. Never treat visual CAD material defaults or the current .15 kg cylinder model as measured mecanum inertials.
5. **Resolve remaining contact/actuator properties separately.** Identify wheel/roller material and floor surface; obtain or measure roller-bearing resistance, loaded effective radius, friction/restitution and suspension resistance only where needed. Record physical motor/encoder polarity, gear ratio, torque-speed limits and command latency. These are prospective measurements requiring a separate appropriate acquisition procedure; no hardware access or actuation is executed by this checklist. Current solver-projected joint efforts and contact impulses do not identify pure motor torque or a friction coefficient.
6. **Prepare a bounded candidate only when core kinematics are supported.** Map every implemented parameter to the ledger; leave remaining assumptions explicit and unfitted. Declare the one intended representation change, unchanged drive/controller/solver/criteria and claim limits. Check numerical/inertial consistency without disguising assumed values as measurements. Freeze source/config/provenance before one fresh original 16-command qualification. Preserve the previously required fresh reproduction/admission protocol after qualification; only an admitted candidate may enter the existing staged matched ViNT development comparison; no automatic sweep, training or navigation follows this specification.

Completion is not an all-parameters-measured requirement for an exploratory simulator. It is traceable core geometry plus explicit assumptions and a frozen empirical qualification. Physical calibration or sim-to-real claims require stronger evidence. If format decoding or variant correspondence remains unresolved, preserve the available sources and report that specific limitation instead of fabricating a plant.
