## Exact construction semantics

The [index builder](https://github.com/hren20/ulvn/blob/e2f47fe3e2757a1ebdc041f4364dddd26a19f9f5/RAVEL/scripts/build_index.py) stores contiguous float32 descriptors. The analyzer separately renormalizes query rows. Preserve that distinction and bind descriptor-row order to the reference-image manifest. Under FAISS L2, returned distances are squared distances; radius 2 is not guaranteed to include every pair of normalized vectors, whose squared distance can reach 4. The source's all-pairs description must not replace the actual `range_search` result or boundary semantics.

The native builder considers each returned pair only when `j > i`. An edge passes only when the geometric match count is **strictly greater** than `tau`; with this fixed mode, zero is rejected and positive counts are retained. Counts populate a symmetric signed-int16 working matrix, with rejected checks temporarily marked -1, then cleared to zero. The weighted saved matrix is uint16. There is no diagonal self-edge. With eight references there are at most 28 distinct checked pairs; the native general counter extracts both images for each pair, so the ceiling is 56 SuperPoint extractions and 28 LightGlue forwards, with zero repeated visual-place encoder forwards.

Matching uses native SuperPoint preprocessing, including its resize-1024 setting, rather than the earlier visual-place encoder transform. SuperPoint settings are NMS radius 4, detection threshold 0.0005, at most 2048 keypoints and border removal 4. LightGlue uses SuperPoint features, match filter 0.05 and depth confidence -1; its default width confidence remains 0.99. This input-dependent point-pruning policy is not parameter fitting. With geometric verification enabled, fewer than eight raw matches yield zero; otherwise the native fundamental-matrix call uses a 3-pixel RANSAC threshold and confidence 0.999, selecting USAC_MAGSAC when available and FM_RANSAC otherwise. Its inlier-mask count supplies the edge weight.

The [native pruner](https://github.com/hren20/ulvn/blob/e2f47fe3e2757a1ebdc041f4364dddd26a19f9f5/RAVEL/scripts/prune_topomap_nx.py) creates every original node, including isolates, adds positive upper-triangle weights, computes a maximum spanning forest, and adds back nonforest edges only when their weight is **strictly greater than 300**. It saves an int32 matrix with sorted original node IDs. Removing isolated nodes in the builder's visualization does not remove them from its saved adjacency matrix. No component may insert chain edges, infer connectivity from ground truth, or replace missing matches with invented counts.

Both the matching counter and matrix builder can suppress technical errors into zero/no-edge outcomes. A successful empty or sparse matrix alone therefore cannot prove successful matching. Qualification instrumentation must retain and reject raised extraction, matching, geometric-verification or index exceptions while preserving native numerical decisions on successful calls. A successful RANSAC call returning no mask remains the native zero-count result, as do insufficient raw matches. Synthetic edge/pruning controls establish only those exercised component boundaries, never an RGB-derived graph result.
