## Question and limits

On a new fixed small sample of development kidnapped starts, does the existing R2 recovery bundle produce more exact-node durable first declarations than B1x, without more wrong confident declarations? This compares the full bundles, not scanning alone. Diagnostic version 2 verified command replay only on two already known scripted cases with initialized proxy state. It did not validate learned-policy memory/handover, intended recovery starts, or efficacy. The original pilot remains INCONCLUSIVE and its remaining 24 attempts must not resume. Its initial mismatch cause remains UNKNOWN.

This proposal does not authorise collection. Executable/configuration review, an exact source/assets/config freeze and a signed launch manifest are required before any next run. No automatic 32-attempt batch is proposed.

## Gate I: initialization validity before efficacy

A separate technical initialization gate must first qualify each intended start and each arm configuration. It may inspect the declared start observations but must invoke no recovery decision, recovery scoring or command selected by the learned model. The learned-policy validation below is limited to pre-kidnap conditioning and handover. Keep these gate attempts separately labelled, preserve every capture/failure and exclude them from recovery denominators. Efficacy starts are prospective for recovery outcomes, not unobserved images after this mandatory gate.

Declare the pre-kidnap conditioning origin per route as the exact initialized root/world-camera/articulation state of that route’s preserved diagnostic v2 reference (repetition 1); freeze the numeric state and provenance in the new manifest rather than infer an origin from the proposed kidnap tuple. Reference and replay both initialize this same known conditioning origin. The proposed new tuple defines only the subsequent kidnap destination. At kidnap set root XYZ/quaternion to that destination with the frozen reference height, zero root linear/angular velocity, preserve joint positions/velocities from the handover, and reset controller integral, held command and applied drive targets to zero. Record actual readbacks before and after; retain learned-policy memory and timestamped observation history. This is a declared physical reset intervention, distinct from post-kidnap observation timing.

Use a fresh process for each launch; pin the version 2 scene/robot/controller/camera and observed renderer settings. One zero-delta bootstrap is unqualified; exactly three fixed eligibility frames follow. Require zero physics callbacks/simulation advance on zero calls and ten callbacks with 1/12 s simulation advance on positive calls; sensor time equals simulation time. Record public timeline separately: bootstrap timeline movement does not imply physics advance. Keep the existing fixed goal/start conditioning and measured DLSS 0 to 2 transition. No adaptive warmup or selecting a later frame.

Replay a frozen 36-command conditioning sequence: first 18 frames (0.04,0,0.15), next 18 (0.04,0,-0.15). Continuous reference and fresh replay must use identical actual commands, feedback, start state and conditioning. The six live history frames at handover are physical steps 6,12,18,24,30,36 (stored 5,11,17,23,29,35), relative ages 30,24,18,12,6,0 steps. Never copy reference RGB into replay. Apply the declared kidnap only after conditioning; retain pre-kidnap policy memory and construct post-kidnap current observation/history by one explicitly frozen common temporal schedule. No six-copy substitution, clock reset, or stale current image. The exact kidnap-to-first-decision history schedule must be implemented and reviewed before freeze; this unresolved executable contract currently blocks Gate I.

For each declared start, two fixed repetitions must compare continuous/reference versus fresh replay within each arm, reference/reference across repetitions and replay/replay across repetitions. Initial/root/world-camera pose, joints/velocities, controller integrals/held targets, applied targets, observation settings, source/assets and all six RGB/time/index guards are mandatory. Reuse diagnostic bounds without recalibration: root XY 0.02 m, yaw 2 degrees, root/world-camera Z 0.002 m, full quaternion 0.2 degrees, joint position 0.001, joint velocity 0.01, root velocity 0.01, controller/held targets 1e-6; each history grayscale MAD <=2.5, age error <=1e-6 s, indices exact, sensor/simulation error <=1e-8 s. Unknown/unsupported readbacks fail closed. Require paired-arm physical/history equivalence at first recovery decision as well; initialized policy state may differ only by the frozen arm schema.

Gate I and Gate H share the same launches: mechanical eligibility first, scripted learned-state comparisons next, then the declared kidnap and post-kidnap initialization/history checks, without a recovery decision. Maximum technical budget is 4 starts × 2 arms × 2 repetitions × reference/replay = 32 fresh processes, plus at most 8 separate efficacy processes after all gates pass (40 total). This is a ceiling, not an automatic launch authorization. The smallest complete technical tranche is one intended start × two arms × continuous/reference and replay × two repetitions = eight launches, opened sequentially with one start/arm reference/replay pair only. Retain histories at the frozen boundary without inspecting efficacy/recovery outputs. Any initialization failure halts the tranche and all expansion. Every further technical tranche requires an evidence-based justification and separately recorded review before execution; the 32-process ceiling is not a mandate to consume it. Any mechanical failure halts immediately. After that pair passes, continue its second repetition and other arm, then the remaining declared starts in manifest order. Any state/history mismatch halts before efficacy. Do not launch all validation processes implicitly. The final executable manifest must enumerate this finite technical schedule, process IDs and maximum count; without that reviewed manifest the gate cannot freeze.

## Gate H: learned-policy handover gap

Use the fixed checkpoint on its original pinned backend/runtime, chain/goal, exact timestamped live input buffers and pre-kidnap schedule. Commands during conditioning remain scripted. Replay the same arm's learned-policy invocations at the same decision indices, independent of requested commands. Compare actual policy class/config, complete hidden state/counters, chain windows, discrete outputs and terminal flags at each invocation and at handover. No proxy substitution. Define complete schema and numerical output tolerances in executable review before freeze; do not import CPU cross-environment equivalence from version 1, which failed.

Only a same-arm continuous/replay comparison can establish learned-state equivalence; R2 and B1x are expected to have different arm-specific state. At kidnap, both receive the same physical observation history and explicitly forced lost entry, with frozen counters/entry accounting. Ground truth must not set the inferred node or choose recovery actions. Gate H failure preserves all attempts and blocks efficacy. Gate I/H cannot be credited by model success on recovery trials. Passing both establishes eligibility only, not recovery competence.

## Outcomes and small-sample decision

Common first-entry horizon: decisions 0..35 after kidnap. First lost-to-tracking transition is a confident declaration. Primary: selected node equals pose-nearest chain node at the predecision pose (Euclidean XY, lowest-index tie break). Secondary: absolute node error <=1, reported separately. Require ten subsequent preterminal decisions without lost re-entry; terminal/filler records never supply durability. Report follow-up pose-node correctness separately: no-reentry is not continuous exact localization.

Assign every efficacy attempt one primary category: correct confident (exact first declaration plus observed durable follow-up); wrong confident (non-exact first declaration, regardless of later correction or +/-1); abstention (no declaration and explicit non-arrival recovery halt); failure (no qualifying declaration, unstable/censored correct declaration, task budget exhaustion without an earlier qualifying primary outcome, crash or invalid/missing evidence). Once a correct first declaration has all ten required follow-up decisions, later task timeout does not reclassify that primary recovery outcome; report the timeout separately. Wrong-first applies only to a first declaration within indices 0..35; later wrong transitions feed the separate full-task guard. Keep failure subtypes and gate invalidation distinct. Durability censoring cannot become success. Preserve late declarations and all preterminal wrong confident transitions.

This four-pair sample is descriptive. A provisional favorable pattern requires R2 strictly more primary correct confident outcomes, no more wrong first declarations in the common horizon AND no more wrong confident transitions across the full preterminal task window than B1x. Report ties/adverse patterns without significance/generalization claims. Integrity failure yields INCONCLUSIVE, never an efficacy conclusion. No recovery-rate target is tuned using these outcomes.
