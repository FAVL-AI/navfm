# F-M1-2 — Unevidenced provenance: a documentation claim whose proof lived only in a gitignored directory

| Field | Record |
|---|---|
| **1. What failed** | `gates/M1/README.md` asserted that random-initialisation runs are stamped `"random_init": true` and that tables built from them are marked "RANDOM INIT — not a result". The evidence for that assertion existed only in `runs/`, which is gitignored. `grep -ril random_init gates/M1/` matched exactly one file: the README making the claim. The archive asserted a property it did not contain. |
| **2. How detected** | M1 verification, by grepping the archive for the evidence the README pointed at, rather than by reading the README. |
| **3. Claim threatened** | The whole contamination barrier around synthetic-noise numbers — the mechanism that stops a smoke-test loss being quoted later as a result. Also the archive's own integrity: an archive whose claims cannot be checked from its contents is documentation, not evidence. |
| **4. Source** | protocol |
| **5. Correction** | `c82e406`. Step 7 of `reproduce.sh` now *asserts* the stamping in-band rather than leaving it to prose, and two metrics files are committed into the archive as the proof: `metrics_randominit_control.json` (`"random_init": true`, null checkpoint) and `metrics_finetuned_roundtrip.json` (`"random_init": false`, with the SHA-256 of the bytes scored). If the stamping regresses, the gate script fails rather than the README going quietly stale. |
| **6. Pre-registered?** | No. |
| **7. Results changed?** | No number moved — no scientific result existed. What changed is that the claim became checkable from the archive alone. |
| **8. Residual uncertainty** | The barrier is asserted by the gate script, not yet by the table generator. Machine-readable evidence classes on every `metrics.json`, and a `make_tables.py` that refuses `scientific_result: false` rows in a results table unless smoke mode is explicitly requested, are M2 work and are not in place. |
| **9. Gate blocked or reopened** | `gates/M1/` reopened and re-archived before `m1-freeze`. No G-gate affected. |

## Why this is the strongest of the three

The other two are things that broke. This one worked exactly as designed and
was still unsupported, which is harder to see and easier to leave standing.
The operating rule it produced is now stated in the paper's methodology section
and in the roadmap's terminology:

> A claim that cannot be demonstrated from the archived evidence is equivalent
> to an unsupported claim.

That is the operational reason gates archive their outputs rather than assert
their properties, and it applies to this repository's claims exactly as it
applies to the upstream implementation's.
