# F-M1-3 — Unsafe deletion: the gate script `rm -rf`'d a path it did not own

| Field | Record |
|---|---|
| **1. What failed** | `gates/M1/reproduce.sh` deleted its working directory with `rm -rf "$WORK"`, where `$WORK` came from the caller. A mistyped argument was therefore a way to lose an arbitrary directory. The script's deletion rule was "delete what the caller asked", which is not a deletion rule. |
| **2. How detected** | M1 verification, reading the script for destructive operations rather than for correctness. Nothing failed — this defect had never fired, which is exactly why it survived. |
| **3. Claim threatened** | No research claim. This one threatens the reviewer: a reproduction script is run by people who have not read it, on machines whose layout its author does not know. |
| **4. Source** | code |
| **5. Correction** | `c82e406`. Marker-file ownership: the script creates `.navfm-m1-workdir` inside any directory it makes, and refuses to delete a path that exists without that marker — "delete only what the gate created". `gates/M1/reproduce.sh:50–61`. Verified behaviourally against a decoy directory rather than assumed from the code. |
| **6. Pre-registered?** | No. |
| **7. Results changed?** | No. No number existed, and this defect had never fired. |
| **8. Residual uncertainty** | The marker protects the workdir specifically. No repository-wide convention forbids destructive operations in other scripts; the invariant is now written in the standing-instructions file, but it is enforced by review rather than by a test. |
| **9. Gate blocked or reopened** | `gates/M1/` reopened and re-archived before `m1-freeze`. No G-gate affected. |

## The invariant it bought

Marker ownership changes the deletion rule from *delete what the user asked*
to *delete only what the gate created*. That is a genuine safety invariant
rather than a defensive check, and it is now a standing rule for every gate
script in this repository.

The verification detail matters as much as the fix: the behaviour was checked
against a decoy directory that the script did not create, confirming refusal,
rather than being inferred from reading the new condition. A guard that has
never been observed to refuse is a guard that has not been tested.
