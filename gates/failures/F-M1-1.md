# F-M1-1 — Specification–execution mismatch: the documented reproduction command did not run

| Field | Record |
|---|---|
| **1. What failed** | `bash gates/M1/reproduce.sh` — the invocation printed in the script's own header and in `gates/M1/README.md` — exited 1 with `ModuleNotFoundError: No module named 'navfm'`. The script defaulted to `PYTHON=python`, and on this machine that resolves to an interpreter without the package installed. |
| **2. How detected** | M1 verification, by *executing* the documented command rather than re-reading the script. No test covered it: the suite exercised the code the gate calls, never the gate's own documented entry point. The control that should have caught this did not exist. |
| **3. Claim threatened** | `gates/M1/README.md`'s central claim — that a reviewer can re-run the M1 evidence chain from a clean checkout. A reproduction gate whose published command fails is not a weaker gate; it is not a gate. |
| **4. Source** | environment |
| **5. Correction** | `c82e406`. The script now preflights both requirements — an importable `navfm` and a resolvable reference clone — and refuses to start with the fix named, rather than failing halfway with a symptom. It deliberately still does **not** guess an interpreter: auto-discovery would silently produce numbers from the wrong torch. `gates/M1/reproduce.sh:23–34`. |
| **6. Pre-registered?** | No. `gates/M1/` is milestone evidence, not a G0–G6 gate, and no pre-registered analysis depended on it. |
| **7. Results changed?** | No number moved — no scientific result existed at the time. The defect was caught before it could contaminate anything, which is the cheapest correction available and is recorded as such rather than as a near-miss. |
| **8. Residual uncertainty** | The fix proves the gate runs under a *declared* interpreter (`PYTHON=…`). Whether it runs under the canonical environment — a fresh clone plus documented prerequisites, reproducing the archived artefact hashes — is unclosed and belongs to M2. |
| **9. Gate blocked or reopened** | `gates/M1/` reopened and re-archived before the `m1-freeze` tag was applied. No G-gate affected. |

## Why this class of defect matters to the programme

The repository claimed one thing and did another, and the gap was invisible to
every test, because the tests checked the components and the claim was about
the entry point. That is the shape of defect the audit method exists to find,
turned on the audit's own infrastructure.

Two invariants were promoted into the standing-instructions file as a result:
gate scripts never infer execution state — they preflight, refuse, and name
the missing requirement — and helpfully auto-discovering an interpreter
weakens reproducibility rather than serving it, because it makes the executed
environment unknowable from the archive.
