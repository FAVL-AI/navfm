# F-M2-4 — Audit-integrity defects: verifications incapable of failing

**Classification:** audit-integrity defect. Same family as
[F-M2-1](F-M2-1.md) — a mechanism that purported to verify a property while
being incapable of falsifying it.

**Authorship acknowledged.** Both entries below were introduced by the
assistant during this session, and both were introduced *while that same
session was enforcing the identical principle elsewhere*. The repository
documents engineering provenance, not blame; the record is worth more for
containing its own author's defects than it would be for cataloguing only
other people's. An audit trail that never catches its author is a prosecution
record. One that does is an instrument.

## Entry 1 — the always-pass environment check

> Audit-integrity defect introduced during construction of the freeze audit.
> The implementation asserted successful verification without comparing the
> preregistered and observed environment identities. Detected during
> adversarial protocol review. Corrected by explicit digest comparison and
> regression tests.

| Field | Record |
|---|---|
| **Root cause** | `Check("environment_identity_recorded", True, …)` was constructed with `passed=True` unconditionally. The fingerprint was computed and rendered, but never compared to anything. |
| **Claim threatened** | Layer A of the G0.c decision rule, which the amendment declares "enforced by `protocol_freeze_audit.py`". A gate executed in a drifted environment — different torch, a leaked `PYTHONPATH`, a shadowed module — would have shown a green Layer A and produced a classification. |
| **Detection mechanism** | Adversarial protocol review (`gates/redteam/trigger3-g0c-amendment-v2-2026-07-31.md`, new defect 6). Not by a test: no test asserted the check could fail. |
| **Corrective action** | Real digest comparison against the identity preregistered in `gates/G0/evaluation_declaration.json`, exposing expected and observed digests and naming differing fields. Absence of a declared identity is a FAIL, not a pass — that being the exact shape of the original defect. |
| **Regression test** | `tests/test_freeze_audit_negatives.py`, four perturbations each forcing a non-zero exit: `PYTHONPATH`, executable identity, a perturbed declared digest, and an absent declaration. |

## Entry 2 — verification filtered so it could not report failure

| Field | Record |
|---|---|
| **Root cause** | Commits in this session verified with `make verify 2>&1 \| grep -E "All checks passed\|Success"`. That pattern matches ruff's and mypy's success lines and matches **nothing pytest prints**. The command reported success whether or not the suite passed. |
| **Claim threatened** | Every commit message in this session asserting a passing suite. Concretely: `8f1722e` entered history with a failing test — the count guard in `test_check_test_population.py`, broken by re-pinning the required population 26 → 33. |
| **Detection mechanism** | Self-detected on the next full run, when the failure surfaced against a subsequent change. |
| **Corrective action** | The guard updated to 33. The filtering habit dropped session-wide; verification now shows pytest's own summary line. Counts asserted in earlier commit messages were re-confirmed by bare `pytest` runs. |
| **Regression test** | None is possible — this is an operator-habit defect, not a code defect, and that asymmetry is itself worth recording. It is mitigated by the standing rule below rather than by a test. |
| **Results changed?** | None. No scientific result existed; `runs/` has never existed. |

## The rule this produced

Promoted to the standing-instructions file:

> **A verification must fail when its subject is absent.** Run it once against
> a deliberately broken state before trusting it against a good one.

This genus has now appeared four times: tests skipping silently when a
dependency was missing (F-M2-1); an environment check that could not fail
(entry 1); a verification command that could not report failure (entry 2); and
— caught while writing the fix — a patch-identity check searching for a marker
string that never existed, which would have failed against a *correctly*
patched clone. That last one was found only by running the check against a
known-good state and disbelieving the result.

Both directions matter. A check that cannot fail certifies nothing; a check
that cannot pass blocks everything and will be deleted by whoever is in a
hurry.
