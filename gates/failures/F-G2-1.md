# F-G2-1 — The E2 collection block is mis-scoped in both directions

**Classification:** a gate whose true reach cannot be read off the archive.
Same genus as F-M1-1 (a gate script inferring execution state) and F-M2-1 /
F-M2-4 (checks that cannot fail). Found by read-only audit; **nothing was
changed**, and no change is proposed here.

**Authorship acknowledged.** Not introduced by this audit — the defect has been
in the repository since `1c612f4`. What is new is that its reach was measured
rather than assumed.

## What the block is supposed to do

`gates/g2_decisions.json:4-5`:

> "Deferral is only honest while it is mechanically impossible to proceed past
> it, which is what `scripts/check_g2_block.py` enforces."

Scoped to E2 in all three places it is described: `PREREGISTRATION.md:150` "No
**E2** collection may begin while any of the four is open";
`scripts/check_g2_block.py:1` "Block collection gate G2 while any deferred **E2**
analysis decision is unset"; and the refusal text at `:106`.

## Over-reach: it refuses work the documentation itself prescribes

The guard is one `if` around the argparse `main()` of the general collector
(`src/navfm/isaac/collect.py:405-408`). It takes no argument describing the run —
no purpose, no episode-count threshold, no E2 discriminator. So it refuses **any**
use of that entrypoint.

Verified by running the command `docs/WORKFLOW.md:156-159` prescribes as the
opening step of Phase 2:

```
python -m navfm.isaac.collect --config configs/collect/m3pro_indoor.yaml \
    --out <scratch> --robot-usd assets/m3pro.usd --episodes 20
```

It prints `collection gate G2 is BLOCKED -- E2 collection may not begin.` and
returns exit 4, creating no output directory. **A 20-episode pipeline smoke test
is by construction not an E2 episode.** The repository documents a step its own
gate refuses.

## Under-reach: the deferral is not mechanically impossible to pass

* `scripts/pilot_collect.py` never imports the checker. It reaches Isaac directly
  and collected the two pilot trajectories without consulting the gate.
* `src/navfm/isaac/collect.py:398-402` declares `--acknowledge-g2-block` with
  `help=argparse.SUPPRESS`. The comment says "see the refusal text", but the
  refusal text never names the flag; `tests/test_g2_block.py` never exercises it;
  and `collection_manifest.json` has no field recording that it was passed. An
  undocumented, untested, unlogged opt-out.
* Nothing downstream is gated at all: conversion, loader-compatibility testing,
  dataset admission (`scripts/register_dataset.py` contains no admission logic),
  training and evaluation all proceed regardless.
* `scripts/pilot_collect.py:186` writes `"admitted_for_training": False` into
  `metadata.json`. Repo-wide grep finds **that single write and no reader**. The
  field that would carry the admission boundary is inert.

## Two further gaps found in the same sweep

**The gate condition has five requirements; the decisions file tracks four.**
`PREREGISTRATION.md:147-151` requires all four decisions to be fixed *"together
with the estimator's type-I error rate measured on simulated null data and its
tolerance"*. `gates/g2_decisions.json` records exactly four entries and no fifth.
`grep` for the type-I requirement in that file returns zero. **If the four are
ever set to FIXED, the co-requirement passes unnoticed** — the checker reads the
JSON, and the JSON does not know about it.

**The short name of decision 1 silently drops a term.** The pre-registration says
*"Estimation software, **optimiser**, and convergence tolerance"*
(`PREREGISTRATION.md:133`). The JSON key and the checker docstring say
"estimation software and tolerance". The optimiser is a separate free parameter,
and the abbreviated name is the one a reader meets first.

## Why this matters more than a scoping tidy-up

The four deferred decisions are the right ones and the deferral is correct. The
defect is that **the archive does not tell you what the gate actually stops.**
A reader of `gates/g2_decisions.json` concludes that no collection can occur; a
reader of the code discovers that one entrypoint is closed, one is wide open, and
a suppressed flag opens the closed one without leaving a trace.

> A gate's reach is part of its evidence. If the scope has to be reconstructed by
> running it, the archive is not self-describing — and the direction of the error
> is unpredictable: this one is simultaneously too strict to permit a documented
> smoke test and too loose to be the mechanical impossibility it claims.

## Deliberately not fixed here

Fixing it means deciding what the gate *should* permit — pilot capture, smoke
tests, library use — and that is a scope decision about the research plan, not a
bug fix. Recorded for the supervisor discussion instead.
